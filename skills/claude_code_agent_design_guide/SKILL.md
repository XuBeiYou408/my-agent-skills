# 工业级 Agent 架构设计与构建指南 (SKILL)

本 Skill 汇总了当前业界最顶尖的 3 种 Agent 架构设计范式：
1. **模式 A：Claude Code 范式** —— 垂直一体化、大而全的企业级 Harness 架构。
2. **模式 B：Pi Agent 范式** —— Unix 极简微核（Microkernel）、数据驱动状态、高性能 ANSI 差分渲染与微虚拟机沙箱架构。
3. **模式 C：企业私有模型 A+B 融合范式** —— 以 Pi Agent 的微核与通用 API 归一化为底座，叠加 Claude Code 的企业级 AST 安全防线、离线 Dream 记忆与集中式权限信箱网桥。

当用户提出设计、架构、开发或构建一个新的 Agent 系统时，必须优先启动**架构选型与推荐对齐机制**，待用户确认路线后再执行后续构建流程。

---

## 一、 架构选型与推荐对齐机制

当用户提出类似“我想设计一个 Agent”、“帮我构思一个 Agent 的架构”、“我要写一个新的 Agent 项目”时，**切勿直接默认使用某种架构**，必须执行以下步骤：

### Step 1: 需求嗅探与选型对比
向幼麟展示 3 种主流架构模式的特点：

* 🏢 **模式 A：Claude Code 垂直一体化企业级范式**
  * **适用场景**：绑定公网顶级模型（如 Claude 3.7）、需要企业级复杂权限审批网桥、多层级团队/项目记忆隔离、内置全功能开箱即用的深度防御。
  * **核心优势**：极致挖掘单一模型潜力、多层级安全 AST 扫描与权限网桥、离线梦境记忆（Auto Dream）。

* ⚡ **模式 B：Pi Agent 极简微核+数据驱动范式（通用推荐）**
  * **适用场景**：需要通配多模型（OpenAI/Claude/DeepSeek/Gemini）、追求极致代码精简与高可维护性、需要高性能无闪烁终端 UI、轻量灵活二次扩展。
  * **核心优势**：800 行 EventStream 极简内核、纯数据驱动 Session 树（文件状态清单不失忆）、传输层多厂商归一化、自研 ANSI 差分渲染、OS/微虚拟机（Gondolin）沙箱。

* 🛡️ **模式 C：企业私有模型 A+B 融合范式（企业私有/自研模型首选）**
  * **适用场景**：企业内部自研/私有化部署大模型（如基于 DeepSeek/Qwen 私有微调或企业 API 中台），既要适配私有模型，又需要企业级安全与团队记忆。
  * **核心架构**：
    * **底层**：使用 Pi Agent（模式 B）的传输层归一化与 800 行 EventStream 微核。
    * **顶层**：叠加 Claude Code（模式 A）的 AST 语法树安检、环境变量洗涤、离线梦境（Auto Dream）记忆与集中式权限信箱网桥。

### Step 2: 给出推荐理据与等待幼麟确认
根据幼麟提出的具体场景（如：模型类型是公网还是私有、团队规模、开发成本），给出一个明确的推荐方案并阐述原因，随后提示：

> **请幼麟确认希望采用哪种架构思路（模式 A、模式 B 或 模式 C）？确认后我们将进入具体的 Step-by-Step 架构拆解与代码构建。**

## 二、 路线 A：Claude Code 架构构建指南

（若幼麟选择模式 A，则按此路线拆解落地）

### 5 大工程维度：
1. **性能与资费治理**：冷热数据解耦（`cache_control` 前缀）、动态工具以 `<system-reminder>` 形式消息流注入。
2. **上下文与记忆长效管理**：就地微压缩（微擦除）、强约束 9 部全量摘要、离线梦境（Auto Dream）复盘固化至 `MEMORY.md`。
3. **深度防御与安全安检**：AST 语法树扫描 20+ 项黑名单、规范化路径比对 Project Root、环境变量敏感词洗涤、集中式权限信箱网桥（`teammateMailbox`）。
4. **运行隔离与渐进自愈**：`git worktree` 独立临时分支、写时复制（CoW）文件快照、渐进式七层防线金字塔重试与自动 Fallback。
5. **架构解耦与状态层**：生命周期 Hook 管道、双轨 AppState Store（Refs + Immutable State）。

---

## 三、 路线 B：Pi Agent 极简微核架构构建指南

（若幼麟选择模式 B，则按此路线拆解落地）

### 4 大微核工程维度：
1. **800 行微核与 EventStream 转向引擎**：采用解耦的异步 `EventStream<AgentEvent>`，集成 Steering Queue 转向与 `AbortSignal`。
2. **数据驱动 Session 树与 File Ops 图谱**：基于树状节点（`SessionTreeEntry`）管理分支，自动提取 `readFiles` 与 `modifiedFiles` 列表写进 `CompactionDetails`。
3. **传输层多模型归一化（`packages/ai`）**：将多厂商思考流与工具调用在传输层统一映射为标准的 `AgentMessage`。
4. **自研 ANSI 差分渲染 & 虚拟机沙箱**：双缓冲区增量 ANSI 矩阵比对，对接 Linux 微虚拟机（Gondolin）或 OS 原生沙箱。

---

## 四、 路线 C：企业私有模型 A+B 融合构建指南

（若幼麟选择模式 C，则按此路线拆解落地）

### 融合架构实施步骤：
1. **Phase 1：搭建微核与 API 归一化适配器**（基于模式 B 构建 800 行 EventStream 核心，在 API 传输层适配企业私有 API/中台 Prefix Caching）。
2. **Phase 2：植入企业级 AST 安全防线**（植入模式 A 的 AST 命令解析器、路径越界比对、敏感环境变量剥离与权限信箱网桥）。
3. **Phase 3：引入数据驱动记忆与离线 Dream 机制**（结合模式 B 的文件状态图谱与模式 A 的离线梦境，将企业规范固化入 `MEMORY.md`）。
4. **Phase 4：交付轻量级 TUI 与沙箱隔离**（配置 ANSI 增量比对终端组件，挂载 OS/微虚拟机隔离层）。
