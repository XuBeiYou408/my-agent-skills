# GitHub 作业前置调研协议 (GitHub Homework Protocol)

> **“让 AI 一上来就写代码，是最高效的低效。用 AI 开发，最贵的从来不是 Token，是方向。”**  
> 不调研就动手，等于让 AI 在黑屋子里重新发明轮子——而且重新发明出来的，常常是个方的。  
> 开源社区最值钱的地方，不是代码本身，而是那句没写进文档里的“当初为什么这么设计”与“那个坑我们花了三周才爬出来”。

---

## 零、 绝对第一铁律：代码零先行 (Zero Code Before Approval)

当接收到新的功能开发或项目构想时，**第一动作绝对不是新建文件、不是敲命令行、更不是输出代码**。  
在完成 GitHub 调研并获得用户对方向的明确确认前，**代码生成通道彻底锁死**。

---

## 一、 抄作业三步法 (3-Step Homework Workflow)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 广度寻标 (Search & Curate)                                │
│    利用 GitHub MCP / 搜索工具，锁定 3~5 个优质开源对标项目   │
├─────────────────────────────────────────────────────────────┤
│ 2. 深度解构 (Deconstruct & Trap Discovery)                  │
│    解构架构设计、核心模块划分，深挖 Issues/PR 里的踩坑雷区  │
├─────────────────────────────────────────────────────────────┤
│ 3. 场景裁量 (Tailored Synthesis)                            │
│    结合用户真实约束，对比各家取舍，提炼最适合本场景的落地方案 │
└─────────────────────────────────────────────────────────────┘
```

### Step 1. 广度寻标 (精选 3~5 个对标项目，严禁贪多)
- 使用 `github` MCP 工具或网络搜索：
  - 搜索同类高 Star、生产验证过、近期仍活跃的经典仓库；
  - 关注官方推荐的标准实现（如 official SDK / reference architecture）；
  - 选取不同风格的对标物（例如：一个重量级全功能方案 vs 一个轻量极简微核方案）。

### Step 2. 深度解构 (深挖 4 个核心维度)
对精选的项目进行针对性分析：
1. **解决什么 & 核心抽象**：它们把核心问题拆解成了哪几个核心实体/模块？
2. **技术栈与依赖选择**：用了哪些久经考验的库？为什么不用其他替代品？
3. **设计取舍 (Trade-offs)**：A 项目为了高性能牺牲了什么？B 项目为了简单放弃了什么？
4. **踩坑历史与边缘情况 (Potholes & Gotchas)**：
   - 翻看 Issues/PR 里的高频 Bug、Breaking Changes 和性能瓶颈；
   - 找出那些“如果不看源码一定会踩三个月”的暗坑。

### Step 3. 场景裁量 (站在巨人肩膀上做剪裁)
- 严禁全盘照搬！结合用户当前的项目背景、性能要求、复杂度承受度与语言生态，做降维与裁剪。

## 二、 编码前强制交付四件套 (The 4 Pre-Coding Deliverables)

在完成调研后，必须以结构化、高可读性的格式向用户输出以下四份核心决策产物：

```markdown
### 📊 1. 技术选型与依赖推荐 (Tech Stack & Rationale)
- **推荐技术栈/依赖库**：（说明选择理由，以及被哪些知名开源项目验证过）
- **放弃的备选方案**：（说明为什么不采用其他方案）

### 🏗️ 2. 系统架构与数据流 (Architecture Blueprint)
- **核心模块划分**：（每个模块的单一职责）
- **核心数据流/交互时序**：（用 Mermaid 流程图或时序图清晰展现）

### 🎯 3. MVP 范围锁死 (MVP Scope Boundary)
- **首版必须包含 (Must-have)**：（仅保留最核心链路，实现闭环）
- **明确不做/后置迭代 (Out-of-scope)**：（果断砍掉边缘需求与过度设计）

### 🗺️ 4. 渐进开发顺序 (Step-by-Step Roadmap)
- **Step 1 (底座与核心模型)** -> **Step 2 (核心流程跑通)** -> **Step 3 (边缘容灾与打磨)**
```

---

## 三、 确认门禁 (The Confirmation Gate)

- 输出调研报告与四件套方案后，主动向用户提问并请求确认。
- **提示示例**：
  > “以上是基于 GitHub 优质开源实现的调研与技术选型方案。请审阅架构与 MVP 范围，确认方向无误后，我将为您启动第一步的工程实现。”
- 只有在用户明确表示赞同或调整意见落地后，才正式进入代码编写阶段。
