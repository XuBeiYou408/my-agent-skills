# 安全代码修复与 Bug 诊断规范 (Safe Code Repair & Diagnosis Skill)

本 Skill 用于在面对任何代码修改、Bug 修复、缺陷排查或异常诊断任务时，强制执行大厂 L7+ 级别的高可靠、防御性、严防破坏的工作流。

---

## 阶段一：工作区安全与状态快照（禁止修改任何代码）

在动用任何代码编辑工具前，必须执行以下前置安全巡检：

1. **检查 Git 状态并报告**：
   - 执行 `git status` 与 `git diff`，主动向幼麟列出当前未提交的改动、暂存区内容与未追踪文件。
   - **绝对红线**：严禁擅自执行 `git commit`、`git reset`、`git checkout .`、`git clean` 或任何可能覆盖、丢弃改动的命令。
2. **工作区隔离与可恢复保护**：
   - 确认工作区安全后，根据项目情况创建独立修复分支（如 `git checkout -b fix/<bug-name>`）或提供明确的可恢复方案（如 stash / patch 备份）。
   - 记录并向幼麟汇报修复前 Commit Hash 与基线状态。

---

## 阶段二：纯读只读诊断与根因分析（严禁盲目猜测）

在定位问题阶段，只读不写，严谨求证：

1. **多维上下文侦测**：
   - 读取项目目录结构、相关依赖定义（如 `package.json`、`requirements.txt`、`go.mod` 等）。
   - 追踪报错模块的完整调用链（Call Stack）、数据流向与已有测试用例。
2. **确定性 Bug 复现**：
   - 编写或运行只读脚本尝试复现 Bug。
   - **缺失信息坦白**：若环境缺失或无法复现，必须明确说明缺少哪些必要信息/上下文，严禁凭空猜测。
3. **最多三大根因假设与证据链**：
   - 最多列出 **3 个** 最可能的根因假说。
   - 每个假说必须包含：
     - **直接证据**（代码行、日志、依赖版本等）。
     - **潜在影响范围**（受牵连的上下游模块）。
     - **最低成本的验证方法**（验证该假说成立的最小探针/测试）。
4. **范围锁死（白黑名单）**：
   - 显式列出 **【允许修改的文件清单】** 与 **【禁止修改的文件清单】**。

---

## 阶段三：幼麟确认与最小化改动实施（核心卡点）

1. **等待审核卡点**：
   - 必须等待幼麟明确确认根因分析和修改范围后，方可动笔修改代码。
2. **最小可控改动 (Minimal Invasive Change)**：
   - 只做精准的单点或最小范围修复，严禁随意重构非相关业务逻辑。

---

## 阶段四：双轨测试、真实报告与回滚兜底

改动完成后，必须进行严格的验证与事实交代：

1. **双轨测试覆盖**：
   - 运行针对该 Bug 的**针对性单元/集成测试**。
   - 运行可能受波及功能的**回归测试**。
2. **诚实测试报告**：
   - 提供实际执行的命令、输出结果及未覆盖的边界测试项。
   - **严格真实原则**：凡是由于环境、网络或依赖等原因无法运行的测试，**必须明确标记为“未验证”**，严禁笼统虚假写成“全部通过”。
3. **次生灾害熔断机制**：
   - 若在验证或修改中引发任何新异常或测试失败，**立即停止一切后续修改**。
   - 第一时间报告当前代码差异（Diff）与明确的一键回滚方案，等待幼麟确认后再行处置。
