# Agent 架构项目深度分析与工程拆解方法论 (SKILL)

本 Skill 专用于**具体 Agent 架构项目与代码仓库的逆向解构与工程分析**。将目标 Agent 项目的核心链路还原为最底层的**第一性原理——4 步固定主循环**：

$$\text{1. 输入与历史 (Context)} \longrightarrow \text{2. 分析与推演 (Think)} \longrightarrow \text{3. 工具与沙箱 (Act)} \longrightarrow \text{4. 反思与自愈 (Observe)}$$

---

## 边界与触发规则

### ✅ 适用场景（自动触发）
* 用户要求分析某个**具体的 Agent 开源项目或代码库**（如 Claude Code、OpenHands、Cline、MetaGPT、自研 Agent 引擎等）。
* 用户要求对某个 Agent 系统进行**架构审查、代码逆向解构、工程机制剖析或瓶颈诊断**。

### ❌ 不适用场景（严禁滥用）
* **从零设计/选型新 Agent**：应引导使用 Agent 设计指引（如 `claude_code_agent_design_guide`）。
* **通用非 Agent 项目架构分析**：应使用代码库全景分析工具（如 `archify`）。
* **常规业务代码编写或单纯 Bug 排查**：应使用通用编码或修复流程。

## 一、 Agent 项目 4 步主循环代码映射与解构维度

在分析目标 Agent 项目代码时，必须快速定位并沿以下四大维度展开深度工程解构：

### 1. 输入与历史端（Context & Cost Optimization）
* **代码定位**：提示词编排模块、Context Manager、Token 计数器、会话存储。
* **核心审查点**：
  * **冷热缓存与资费**：是否利用 `cache_control`（如 Prompt Caching）实现静态 System Prompt / 历史上下文的冷前缀复用？
  * **上下文压缩瘦身**：是否具备就地微压缩（Micro-Compaction）、结构化摘要提取或滑动窗口保活策略？
  * **长效记忆与沉淀**：是否实现离线梦境（Auto Dream）、向量检索长期记忆或跨会话技能沉淀？

### 2. 分析与推演端（Thinking Engine & UI Rendering）
* **代码定位**：LLM 调用主循环（ReAct Loop / Planner）、流式解析器、状态管理（State Store）。
* **核心审查点**：
  * **推理与思考控制**：是否支持思考预算控制（Extended Thinking）、动态工具注入/按需裁剪以降低模型注意力负担？
  * **引擎与 UI 解耦**：思考流、执行流与 UI 渲染是否解耦？是否具备双轨 State Store 与高性能差分（Diff）流式渲染？

### 3. 调用工具与沙箱端（Tool Execution & Sandbox Security）
* **代码定位**：Tool Registry、Command Executor、FileSystem Manager、权限审批流。
* **核心审查点**：
  * **输入过滤与语法安检**：是否有 AST 语法树危险指令拦截、路径越界检查（Path Traversal 防护）及环境变量清洗？
  * **防破坏与回滚机制**：是否具备写时复制（CoW）快照、Git Worktree 隔离、物理沙箱容器或 `/rewind` 快速回滚能力？
  * **多智能体权限隔离**：多 Agent 协作时是否有集中式权限审批网桥或消息隔离信箱？

### 4. 观察反思与容灾自愈（Resilience & Error Recovery）
* **代码定位**：LLM 异常拦截器、工具执行报错重试逻辑、Fallback 策略。
* **核心审查点**：
  * **渐进式容灾金字塔**：遇到异常时是否具备分级自愈链路（指数退避重试 $\rightarrow$ 速率过载挂起 $\rightarrow$ Token 截断续写 $\rightarrow$ 备用模型 Fallback 降级 $\rightarrow$ 会话快照落盘与恢复）？
  * **自我反思死循环防御**：是否有最大步骤熔断（Max Steps Limit）、反思发散抑制与死循环检测机制？

## 二、 Demo 粗暴做法 vs 目标项目架构师做法对比框架

在剖析项目的具体技术实现时，严格采用以下 Markdown 四维对比结构：

* **🔴 Demo 粗暴做法**：描述新手/常规简易实现中的低效或高危写法。
* **⚠️ 这样做的问题是什么？**：直击并发崩溃、显存/Token 爆炸、命令注入、死循环等工程缺陷。
* **🟢 目标项目架构师做法**：结合项目代码中的实际模块与机制，详细阐述其工业级解决方案。
* **💡 为什么这么做？**：从第一性原理、成本收益比（ROI）与系统高可用角度阐述核心优势。

## 三、 结构化总结规范

分析结束时，必须输出一张结构化的【4 步闭环优化与防护一览表】，并附上项目的【工程成熟度评级与优化建议】：

| 主循环步骤 | 🔴 Demo 粗暴做法 | 🟢 目标项目实际架构/专业做法 | 🌟 获得的根本优势 |
| :--- | :--- | :--- | :--- |
| **1. 输入与历史** | 盲目滑动窗口截断 / 全量重传 | 冷热缓存复用 + 微压缩瘦身 + 离线记忆固化 | 资费骤降 70%-90%，超长上下文抗失忆 |
| **2. 分析与推演** | 同步全量阻塞 / 界面频繁重绘 | 推理流分离 + 动态工具裁剪 + 状态差分渲染 | 低延迟响应，零卡顿零闪烁，降低模型幻觉 |
| **3. 工具与沙箱** | 裸奔 `exec()` / 本地直接读写 | AST 拦截 + 环境变量洗涤 + Git/CoW 隔离快照 | 杜绝危险提权与误删，支持原子级一键回滚 |
| **4. 反思与容灾** | 捕获报错直接抛出或无限重试 | 渐进式容灾金字塔 + 跨模型 Fallback + 熔断 | 具备工业级自愈韧性，杜绝死循环与崩溃 |
