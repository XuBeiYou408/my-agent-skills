# Agent 4 步主循环与深度防护分析方法论 (SKILL)

本 Skill 旨在将任何复杂的 Agent 架构拆解为最底层的**第一性原理——4 步固定主循环**：

$$\text{1. 用户输入与历史} \longrightarrow \text{2. 大模型分析 (Think)} \longrightarrow \text{3. 调用工具 (Act)} \longrightarrow \text{4. 观察反思与容灾 (Observe)}$$

当用户要求“帮我分析某个 Agent”、“讲解这个 Agent 的架构”或进行技术剖析时，必须严格按照以下**四大主循环模块**展开优化与防御拆解：

---

## 一、 4 步主循环的优化与防御解构框架

### 1. 输入与历史端优化（Context & Cost）
* **冷热缓存与资费**：是否做了系统 Prompt / 冷前缀 `cache_control` 打包？
* **上下文瘦身**：是否实现了就地微擦除（Micro-Compaction）与强约束摘要？
* **长效记忆**：是否具备离线梦境（Auto Dream）记忆复盘与固化机制？

### 2. 分析与推演端优化（Thinking & Rendering）
* **思考预算与降维**：是否支持 Extended Thinking 推理流与动态工具注入？
* **解耦与渲染性能**：引擎与 UI 是否解耦？是否有双轨 State Store 与高性能差分渲染？

### 3. 调用工具端防护（Security & Sandbox）
* **命令行与路径安检**：是否有 AST 语法树黑名单扫描、路径越界隔离与环境变量洗涤？
* **防毁坏与回滚**：是否有写时复制（CoW）物理快照、`/rewind` 一键恢复与 Git Worktree 隔离？
* **权限网桥**：多 Agent 或子进程是否有集中式权限信箱网桥（`teammateMailbox`）？

### 4. 观察反思与容灾自愈（Resilience Pyramid）
* **渐进式防线金字塔**：遇到报错时是否有层层降级（指数退避 $\rightarrow$ 过载挂起 $\rightarrow$ Token 续写 $\rightarrow$ 模型 Fallback 降级 $\rightarrow$ 落盘恢复）？

## 二、 Demo 开发者 vs 专业架构师四维对比法

在拆解具体技术点时，配合以下 Markdown 标准对比结构：

* **🔴 Demo 开发者做法**：描述初学者或常规 Demo 的简单粗暴做法。
* **⚠️ 这样做的问题是什么？**：剖析延迟、崩溃、失忆、命令注入等缺陷。
* **🟢 专业架构师做法**：详细阐述目标 Agent 的工业级解决方案与机制。
* **💡 为什么这么做？**：阐述第一性原理与量化物理优势。

## 三、 终极总结对比表模版

分析结束后，必须附带一张结构化的【4 步闭环优化防护一览表】：

| 主循环步骤 | 🔴 Demo 粗暴做法 | 🟢 目标 Agent 优化防护做法 | 🌟 获得的根本优势 |
| :--- | :--- | :--- | :--- |
| **1. 输入与历史** | 盲目滑动窗口截断 | 冷热缓存 + 9 部摘要 + 离线 Dream | 资费降 90%，永久抗失忆 |
| **2. 大模型分析** | 全量清屏刷新 UI | 动态工具降维 + 双缓冲区差分渲染 | 60 FPS 零闪烁，极低 CPU |
| **3. 调用工具** | 裸奔 `exec()` 执行 | AST 扫描 + 环境变量洗涤 + CoW 快照 | 绝对物理安全，可一键回滚 |
| **4. 观察反思** | 报错直接抛异常崩溃 | 渐进式七层容灾金字塔与自动 Fallback | 系统极度健壮，高可用自愈 |
